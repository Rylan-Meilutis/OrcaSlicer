# Learned print-time estimates

The learned estimate supplements, rather than replaces, the deterministic G-code time estimate. Firmware-controlled heating, cleaning and tool handling can take time not represented by explicit motion. Completed print observations measure the combined discrepancy; they do not identify individual stage durations or validate thermal stress predictions.

Learning is opt-in. The OctoPrint adapter imports only a successful completed attempt whose file SHA1 matches the selected local G-code. Standard file metadata exposes the last attempt, not a complete historical job log. Repeated imports of the same execution do not create additional observations. OctoPrint's completed print time excludes pauses and includes heating; failed or cancelled totals are not valid completed observations. No additional validation prints are required.

An explicit refresh makes two read-only requests: current job metadata to find its local file path, then that file's metadata. It does not crawl history, download G-code or send printer commands. Each response is limited to 1 MiB and each request to seven seconds. The successful attempt timestamp must not precede the file upload timestamp, preventing an overwritten path's older history from being attributed to new bytes. Missing provenance is rejected. Credentials and raw host URLs are not written to learning history or diagnostic logs.

Compatibility combines the host identity, a user-declared printer setup revision, the source OrcaSlicer version and the complete embedded configuration fingerprint. The generation timestamp is excluded so that different jobs remain comparable. The setup revision is not firmware detection: users must change it after firmware, calibration or other printer changes affecting timing. The source configuration includes machine limits, tool mapping, material settings and custom macros. Geometry can differ while configuration remains compatible. Every configuration value is retained, including repeated legacy/project keys. Missing or malformed source provenance causes an unavailable result rather than guessing from current presets.

Preview exposes an explicit update action and consent dialog. The required setup revision is stored locally per host. Background results are accepted only while the preview result identity, source filename, host and setup revision still match, preventing a stale request from updating another job. The raw slicer estimate remains unchanged.

Features comprise the baseline duration and counts of tool transitions, heating waits, cleaning/parking commands and calibration/homing commands. These counts describe similar jobs; they are not assigned invented durations. Motion duration remains unknown when it cannot be extracted separately from the baseline, which already contains some tool-handling allowances.

At least three distinct compatible completed executions are required. Each numerical feature must be within twenty percent of its larger value in the candidate and observation; zero matches only zero. The predicted total is the candidate baseline plus the median observed residual (actual active time minus that observation's baseline). This adds unexplained time once and does not apply a global speed multiplier. The accompanying range is the minimum and maximum transferred observed residual, not a statistical confidence interval or a guarantee. Predictions abstain outside the observed neighborhood or when a transferred range is invalid.

The history holds at most 128 observations in bounded local JSON storage. Source extraction limits the file to 256 MiB, individual lines to 256 KiB and embedded configuration to 4 MiB. Cancellation checkpoints bound background work; no large G-code copies or serial logs are retained. The original estimate remains available when learning has insufficient observations or import is unavailable.

The history file is capped at 1 MiB and replaced using a private sibling and rename; failed replacement does not fall back to truncating the previous history. A previously learned compatible estimate remains available if the requested import finds no matching completed job or the server is unavailable. Import status is separate from estimate availability.

OctoPrint interfaces: [job information](https://docs.octoprint.org/en/main/api/job.html), [file and print statistics](https://docs.octoprint.org/en/main/api/datamodel.html), and [printing events](https://docs.octoprint.org/en/main/events/index.html). Stage-specific learning would require actual execution telemetry; host send times alone are not firmware execution times.
